# 规范索引与总则

本目录是 [AGENT.md](../../AGENT.md) 的展开细则。**阶段说明**：工程骨架、令牌真源、Android target、动效内核与 P3 基础组件（Scaffold、顶栏、Button、Switch、Slider、Card、Icon）已落地（有单测，Android 真机已验收）；文中关于其余组件、动效逐帧对比、golden、Web 入口、性能基准与 CI 的条目仍是约定目标，不得据此宣称功能已实现。落地过程中若发现约定无法执行，按本文末尾的「规范变更流程」修订，而不是悄悄绕过。

## 1. 优先级与冲突

2026-11-17 增量：双语使用文档入口为 `docs/README.md` / `docs/zh_CN/README.md`，当前覆盖本轮修复组件；Desktop UI 与 Slider golden 已落地，CI 配置已编写但未验证远端运行。完整逐帧、性能与全组件文档仍待验收。

1. `AGENT.md` — 唯一权威规则。
2. `docs/spec/*.md` — 分领域细则，不得与 `AGENT.md` 矛盾。
3. 已落地的源码 — **事实源**。规范与代码不一致时，在同一改动中修正其一，并在 PR 说明取舍；不得让文档长期说谎。
4. `AGENTS.md`、README、注释、历史提交 — 导航与背景，不构成规则。

某个具体组件的实现细节以**该组件源码**为准；本项目借鉴的外部项目（如 miuix）只作组织方式参考，其规则**不自动生效**。

## 3. 术语

| 术语 | 含义 |
| --- | --- |
| `Spec ID` | 组件或动效的唯一编号，格式 `CMP-<NAME>` / `MOT-<CATEGORY>-<NNN>`；一旦分配不复用、不改名 |
| `targetBaseline` | 该实现所对齐的 OxygenOS 版本 + 设备/系统版本 + 采集日期 |
| `reference` | 可复核的原始凭据：录屏文件、帧号、帧率、测量方法、采集设备 |
| `Evidence Level` | 证据等级 E0–E3，定义见 §4 |
| `Design Token` | 有 ID 的静态视觉值，来自 `design/tokens/*.yaml` |
| `Motion Token` | 有 ID 的时长/缓动/弹簧/编排参数，同样来自令牌真源 |
| `Capability` | 平台是否具备某能力（模糊、触觉、高刷…），由 `LocalOxygenCapabilities` 暴露 |
| `Parity` | 实现与 reference 在指定维度上的一致程度；必须写清测量方法，不接受主观描述 |
| `Golden` | 被批准的基线截图/帧序列，用于回归 |
| `draft / in-review / verified` | 实现状态；只有满足 §4 与 `workflow.md` 门槛才可标 `verified` |

## 4. 证据等级与状态

「完整复刻」的敌人是凭感觉填参数。所有对外宣称的数值必须能追溯到证据。

| 等级 | 定义 | 允许用途 |
| --- | --- | --- |
| `E0` | 猜测、类比、无来源 | 仅可作占位，必须带 `TODO(E0)` 且**不得**进入 `verified` |
| `E1` | 视觉比对：肉眼对照截图/视频 | 结构与层级草案，需注明主观性 |
| `E2` | 定量测量：逐帧录屏取时间点/位移/缩放，或曲线拟合 | 可作为 `verified` 的最低门槛 |
| `E3` | 系统侧可复核数据：公开的框架动画参数、系统资源/属性 dump、可重复脚本输出 | `verified` 首选 |

升级要求：低等级 → 高等级必须在同一改动中补上 reference 路径与测量方法；降级必须记录原因。状态 `verified` 还需同时通过 `workflow.md` 的全部门禁。`E3` 的取得方式必须合法合规，不得以提取或再分发专有资源为代价。

## 5. 合规边界

- **只复刻可观察行为**：布局规律、时序、曲线、状态转换、交互反馈；不复制专有素材。
- **资源**：图标、插画、字体、音效、壁纸自绘或使用有明确宽松许可的第三方素材，并在 `docs/spec/` 或 `NOTICE` 登记来源与许可证。
- **参考凭据**：`catalog/reference/` 只允许存放用于本地验收的最小片段（短录屏、帧序列），不进入公开发布物与制品；不得包含个人信息、账号数据或受版权保护的完整内容；仓库维护者有权要求移除。
- **表述**：文档站、README、制品元数据一律标注 `Unofficial / 非官方`；不使用厂商 Logo、商标做身份暗示，不宣称兼容性认证。
- **禁止**：反编译提取并复制资源、绕过权限、模拟系统服务、收集用户数据。

## 6. 文档语言与对应

- 规范（`AGENT.md`、`docs/spec/`）以简体中文为准，标识符与专有名词保留英文。
- 面向使用者的文档站采用**中英双语一对一**：`docs/components/{slug}.md` ↔ `docs/zh_CN/components/{slug}.md`，章节、示例、参数表必须逐项对应；任何时候不允许一种语言独有内容。
- 代码注释、KDoc 中英均可，单文件内保持一致。

## 7. 规范变更流程

规范本身是受版本约束的产物：

1. 在 PR 描述中写清**动机、受影响组件/动效、迁移成本**。
2. 规则变更必须同步：`AGENT.md` 摘要、对应细则、组件模板、catalog 校验项、CI/门禁脚本、双语文档（若影响公开 API）。
3. 不放宽已 `verified` 实现的验收门槛；确需放宽时，逐条列出受影响 `Spec ID` 并重新验收。
4. 禁止用「先合并、后补文档」的方式引入规则例外。
